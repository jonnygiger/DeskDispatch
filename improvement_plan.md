## A. Fix logical faults

1. **Make first boot work.**  The compose `migration` service pre-creates `users`, then the app's `sqlx::migrate!` fails with `relation "users" already exists`. Delete the ad-hoc SQL and add `migrate` and `create-admin` subcommands, since the image ships only `app` and not the `seed` binary. Remove the hard-coded admin hash for password `test` (`ADMIN_PASSWORD` is never read). Create the bucket through the SDK with credentials, not an unauthenticated `curl PUT … || true`.

2. **Fix step reordering.**  Move Up/Down and `compact_positions` fail with a unique-key violation on `(automation_id, position)`, because the swap's first `UPDATE` collides with its neighbor. The `let _ =` swallows the error, so the click silently does nothing. Make the constraint `DEFERRABLE INITIALLY DEFERRED`, lock the automation row in every step mutation, and propagate errors. With only tens of steps per automation, consider dense integer positions instead of floats.

3. **Fix deletion and referential integrity.**  Steps with run history, branch-target steps, and any automation that has ever run cannot be deleted (FK violations), and the handlers redirect silently. Soft-delete or archive automations and steps that have history. Use `ON DELETE SET NULL` plus a "used by" warning for branch targets and variables.

4. **Give runs a real state machine.** `complete` has no `AND status='running'` guard, so a worker's late "succeeded" overwrites an operator's "cancelled" (or a `lost` run). `step-result` accepts reports in any state, and cancel marks the run `cancelled` instantly while the worker may still be clicking. Add `cancel_requested_at` with a `cancelling` state, enforce legal transitions in SQL, and return the run's server-side state in the heartbeat. Add `UNIQUE (worker_id) WHERE status='running'`, because `next-assignment` currently lets a worker claim a second run.

5. **Fix dispatch targeting.** Manual runs have `schedule_id NULL`, so any worker can claim them. Add `target_worker_group_id` to `task_runs`, snapshotted at queue time, and a selector on Run Now. Run-now only checks that the automation exists, so also refuse draft, archived or empty automations. Snapshot the dispatched payload so resume isn't affected by mid-run edits, and check the worker's screen resolution before dispatch.

6. **Make the worker protocol idempotent and versioned.** `step-result` is a plain `INSERT`, so retries create duplicates. It doesn't validate `step_id` or `variable_id` against the run's automation, and variable updates run one query per item. Add a worker-supplied `seq` with `UNIQUE (task_run_id, seq)` and `ON CONFLICT DO NOTHING`, validate IDs, batch with `UNNEST`, and accept a single payload shape (both `captured_r` and `captured_rgb[]` are accepted today). Reject outdated `agent_version`s and return poll and heartbeat intervals from the server.

7. **Fix the scheduler.** `schedules.timezone` is selected but never used, so cron always evaluates in UTC (and there's no `chrono-tz` or `jiff` dependency). A failed `compute_next_run_at` silently writes `NULL` and the schedule never fires again. There is no overlap or catch-up policy, so queued runs pile up while a worker group is offline. Add timezone support with DST tests, an overlap policy (skip/queue/allow), queue-age expiry, and loud failure.

8. **Repair the bitmap commit flow.** `GET /bitmaps/commit` mutates state without CSRF and never validates `key`, so any bucket object can be registered as a bitmap. Per the README, deleting a bitmap deletes its S3 object. A failed dimension probe falls back to a fake 100×100 and still inserts the row, the whole object is buffered in memory first, and any image format is accepted. Convert it to a confirmation page plus a CSRF'd POST, require the `bitmaps/` prefix bound to the uploader, fail on probe errors, use a ranged GET with `image::Limits`, accept PNG only, and make it idempotent.

9. **Fix URL and endpoint config.** The commit redirect is built from the request's `Host` header and uses `http` only when the host contains "localhost", so a LAN install at `http://192.168.x.x:3000` gets `https` and breaks. Compose sets `S3_ENDPOINT=http://rustfs:9000`, which will almost certainly end up in presigned URLs the operator's browser can't resolve. Please check this from a second machine. Add `PUBLIC_BASE_URL` and `S3_PUBLIC_ENDPOINT`, and make `S3_ENDPOINT` a real `Option` (it's always `Some`, so real AWS S3 can't be used).

10. **Make worker status truthful.** The dashboard counts `status='online'` on a self-reported column that nothing resets, and it excludes `busy` workers. Derive status from `last_heartbeat_at` at query time. Have the sweeper also expire stuck `recording` sessions, because an active recording makes `next-assignment` return `start_recording` on every poll and blocks that worker from receiving runs.

## B. Security hardening

11. **Fail fast on bad config.** Production boots with the built-in `session_secret` default, DB password and S3 keys. Compose ships the same values with `APP_ENV=production` and publishes the Postgres and RustFS ports. Refuse to start in production on defaults and use `secrecy::SecretString`, since `Config` derives `Debug` over its secret fields. Add `.env` to `.gitignore` (only `/target` is ignored today), move compose secrets out of the file, and publish only the app port.

12. **Harden login.** The client IP comes from client-supplied `X-Forwarded-For` and `X-Real-IP`, so the limiter is bypassed by varying a header. Check and record are separate calls, so parallel requests exceed the limit. The map never evicts, so random usernames grow it without bound, and there is no per-IP limit. Unknown usernames return before any hash, so timing reveals valid usernames, and Argon2 runs directly on the async runtime. Add trusted-proxy config, an atomic check-and-record (or `governor`), eviction, a dummy-hash verify, and `spawn_blocking` behind a semaphore.

13. **Fix sessions, cookies and CSRF.** Add `Secure` and the `__Host-` prefix, idle and absolute expiry, a purge job (expired sessions are never deleted), and revoke other sessions on password change. Compare CSRF tokens in constant time (currently `==`). Replace the middleware that buffers every POST body with a typed `CsrfForm<T>` extractor plus `Origin`/`Sec-Fetch-Site` checks, and delete the 8 duplicated per-handler checks. On expiry, redirect to login with a return path instead of a bare 403 that loses the user's form.

14. **Add response hardening.** Send a CSP with `script-src 'none'` (this is a zero-JS app, so it's nearly free), plus `frame-ancestors 'none'`, `form-action 'self' <s3-origin>`, `nosniff`, `Referrer-Policy` and HSTS. Fix the CSS-injection path: `magnifier.rs` interpolates `image_url` raw into `url('{}')`, and `get_pick_region_handler` takes it from a query parameter. Derive media URLs from IDs server-side and CSS-escape. Gate `/dev/magnifier-verify` (registered unconditionally) behind a debug feature. Split `/healthz` into a dependency-free `/livez` and a cached `/readyz`.

15. **Fix worker credentials.** Registration tokens are stored in plaintext, never expire, and are written into `audit_log.details` on create and rotate-key. Store a hash plus expiry and keep tokens out of audit details. Generate API keys from `OsRng` with a recognizable prefix (today it's two UUIDv4s, about 244 bits, not the documented 256 — safe but inaccurate). Add `UNIQUE` on `api_key_hash` and use `NULL` instead of an empty `bytea` for "no key". Allow two-key overlap on rotation and rate-limit worker endpoints.

## C. Performance

16. **Run a schema-hardening migration.**  The DB accepts RGB 999 and −3, tolerance 9999, negative coordinates, `post_delay_ms = −5000`, and branch rows with NULL targets. Branch targets can also point into another automation. Add CHECK ranges, `NOT NULL` targets, a composite FK `(automation_id, id)`, `UNIQUE (lower(username))`, and `DEFAULT gen_random_uuid()` on `sessions.id`. Replace the current migrations, which are dated 2025-01-01, with real timestamps; the first one is empty.

17. **Do an index and query-plan pass.**  Only primary keys and one partial index exist. There is no index on `task_worker_pcs.api_key_hash` (a scan on every worker request), `task_run_steps(task_run_id)`, `task_runs(automation_id, worker_id)`, `sessions(user_id, expires_at)` or `audit_log(created_at)`, and the FK cascades will scan too. Add them, change `(status, queued_at) WHERE status='queued'` to `(queued_at) WHERE status='queued'`, run `EXPLAIN ANALYZE` on the claim, sweeper and run-list queries, and move `/runs` to keyset pagination.

18. **Fix the pool, polling and query shape.** The pool is `max_connections(5)` with no acquire timeout. Each `next-assignment` costs about five round-trips, and although the README promises long-poll, the handler returns immediately. Make the pool size configurable, add timeouts, fold auth, heartbeat and claim into one statement, and implement real long-poll with `LISTEN/NOTIFY` without holding a pooled connection while waiting. Load-test with around 300 simulated workers.

19. **Cut page weight and HTTP cost.** Static assets have no `Cache-Control` or `ETag`, and there is no compression layer. The pixel-grid panel inlines long gradient strings on every step card, and media redirects appear to have no cache headers. Fingerprint static files with immutable caching, add `CompressionLayer`, move gradients into CSS classes with custom properties, and cache media redirects for less than the presign TTL. Put live run status in a small auto-refreshing `<iframe>` so the heavy step list isn't reloaded every 3 seconds, and stop refreshing at a terminal state.

20. **Add retention and storage lifecycle.** I found no pruning of `sessions`, `audit_log`, `task_run_steps` or screenshots. Add config-driven retention jobs, an S3 lifecycle rule for abandoned `tmp/` uploads, and an orphan-object GC. Delete DB rows first and then the S3 object, so a failure can't leave rows pointing at missing files.

## D. Usability

21. **Add a feedback layer.** There is no flash-message mechanism. Failed deletes, forbidden actions and "Run now" all end in silent redirects, while other routes return plain-text 403s. Add flash cookies, styled 403/409 pages and field-level form errors. Use `RequireEditor` everywhere, because the bitmap handlers use an `== Viewer` deny-list that would fail open for any future role.

22. **Improve Run Now and the run pages.** Link to the new run after queuing it and add double-submit protection. Allow parameter overrides (parameters are constants per automation today) and worker-group selection. Show "cancelling…" until the worker acknowledges.

23. **Validate automations before they can run.** Add an Activate gate that lints dangling or cross-automation branch targets, cycles with no exit, variables read before being written, type mismatches, deleted bitmaps, and coordinates outside the target resolution. Add a server-side run timeout and max step count, since branch GOTOs can loop forever. Add wait-until timeouts and retries to `find_*` and `branch` steps, because fixed `post_delay_ms` sleeps are the main source of flaky GUI automation.

24. **Ship user management.** The README's `[TODO]` is accurate here: there are no `/users` routes, so the seed binary is the only way to create a user. Add create, edit, deactivate and password reset, force a password change on bootstrap accounts, protect the last admin, and revoke sessions on deactivation.

25. **Make the zero-JS pickers robust and accessible.** `<input type="image">` reports coordinates relative to the rendered box, so any CSS shrink or browser zoom breaks the server's scale math. Render at fixed dimensions inside a scroll container. Keyboard activation submits (0,0), so treat that as "no pick" and make numeric entry a first-class path. Add a "pause auto-refresh" link (WCAG 2.2.1) and proper `<label>`s. Add Playwright checks on Chromium, Firefox and Safari with 4K screenshots, since the 20× backgrounds reach about 38,400 px wide.

## E. Rust engineering (2026)

26. **Restructure the code.** `routes/automations.rs` is 4,758 lines and `post_create_step_handler` alone is about 800. Split by domain, with each module exposing `fn router() -> Router<AppState>`. Add `build_router(state)` in `lib.rs`, because 8 of 10 test files copy the route table. Add a service/repository layer, rename the package from `app` to `deskdispatch`, and extract worker API types into a `deskdispatch-protocol` crate so the separate agent can't drift.

27. **Type the domain and errors.** Add an `AppError` (`thiserror`) with `IntoResponse` so handlers can use `?`. The claim handler is about 180 lines of repeated error blocks, and about 80 sites use `let _ = sqlx::query(…)`. Replace `String` statuses and `is_valid_*` helpers with `sqlx::Type` enums, and add newtype IDs. Write audit rows inside the mutating transaction. Adopt `sqlx::query!` with a committed `.sqlx/` (0 of 227 queries are compile-checked, contrary to the README). Add `#![forbid(unsafe_code)]`, a `[lints]` table denying `unwrap_used` outside tests, and `#[expect]`.

28. **Stand up CI and supply-chain checks.** There is no `.github/`. Add `fmt`, `clippy -D warnings`, `nextest`, `cargo deny`/`audit`, an unused-dependency check, an MSRV job and an image scan. Add `rust-toolchain.toml` and `rust-version`, and remove `--ignore-rust-version`, which suggests some dependency needs a newer compiler than the pinned 1.85. Rework the Dockerfile with `cargo-chef` or BuildKit caches and `--locked`. Run as a non-root user on a distroless base, drop OpenSSL (sqlx uses rustls), replace `curl` healthchecks with a binary subcommand, and pin the `rustfs:latest` image. Remove the committed `rendered_templates/` or turn it into `insta` snapshots.

29. **Improve operability.** `axum::serve` has no graceful shutdown, and as PID 1 without a signal handler the process won't react to `docker stop`. The sweeper and scheduler share one bare `tokio::spawn`, so a panic silently stops scheduling. Add `with_graceful_shutdown` and a `CancellationToken`, and run background tasks in a supervised `JoinSet` with DB timeouts and `MissedTickBehavior::Skip`. Add `tower-http` layers (trace, request-id, timeout, catch-panic). Default the log level to `info` (it is `app=debug` even in production) and expose Prometheus metrics on a separate port.

30. **Replace the test strategy.**  The integration helper's `INSERT INTO sessions (user_id, expires_at)` fails against the real schema because `id` has no default, so those tests can't pass with a DB. 19 of 22 print "skipping" and go green without one, which is how the reorder bug slipped through. Move to `#[sqlx::test]` or testcontainers (Postgres and S3). Add tests for worker dispatch, step-result, complete and the sweeper, which have none (the scheduler has only cron-parsing tests). Add `proptest` for ordering and the run state machine, OpenAPI via `utoipa` with contract tests, and a CI check that docs match routes.
